# Frontend structure: flat components, shared types, composables for cross-page fetches

The Nuxt frontend had no conventions yet for where logic should live as it grew past its initial five pages. Each page (`work-weights.vue`, `log.vue`, `programme.vue`, `personal-records.vue`, `index.vue`) had grown into a single file mixing data-fetching, mutation handlers, and template — up to 246 lines for `log.vue`, which alone rendered three distinct UI modes (choose workout / fill in reps / show result). Worse, three DTOs (`Lift`, `Programme`, `WorkWeight`) were independently redeclared per page with inconsistent shapes, the "fetch a lift's Work Weight, treat a 404 as not-yet-Ramped" pattern was copy-pasted verbatim in two places, and the Training Phase → Workout B third-lift mapping existed twice (`programme.vue`'s local `PHASE_LIFT` and `utils/workoutLifts.ts`'s `PHASE_THIRD_LIFT`) with different formatting, which is exactly the kind of drift duplicated domain logic invites.

We adopt: a **flat `app/components/`** directory (no domain subfolders) for UI extracted out of oversized pages — the app is currently ~950 lines total, so folder-per-domain grouping would be organizing for a scale that doesn't exist yet; revisit this once `components/` holds enough files that a flat listing stops being scannable. A **single `app/types/index.ts`** holds every DTO shared across more than one file, so the API's shape is defined once instead of re-guessed per page. **Composables** (`app/composables/`) hold fetch logic reused across pages — `useWorkWeights` replaced the duplicated Work-Weight-fetch-with-404-fallback — while **`app/utils/`** stays reserved for pure, side-effect-free functions (`formatLiftName`, `formatDate`, `liftsForWorkout`). Pages themselves stay orchestration-only: fetch calls, local UI state, and wiring child components together, with no inline markup for more than one UI mode.

We also added ESLint (`@nuxt/eslint`), Prettier, and Vitest at the same time, deliberately, while the codebase is still small enough that retrofitting conventions is cheap. `liftsForWorkout` and `WorkoutPicker.vue` both had latent unsafe-array-indexing bugs (`string | undefined` treated as `string`) that `vue-tsc`'s `nuxt typecheck` caught immediately once wired in — evidence for doing this now rather than after more code accumulates around the gap.
